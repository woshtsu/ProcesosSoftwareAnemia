**Guía de trabajo semana 1 – 2026-20**

**Guía de trabajo – Eje 1: Enfoque de procesos de la organización**

**Curso:** Procesos de Software
**Unidad:** Diseño de procesos de software con entrega de valor
**Eje temático:** 1. Enfoque de procesos de la organización
**Proyecto guía:** *Plataforma de Seguridad Vial Inteligente para la Carretera Central*

El proyecto plantea diseñar un sistema predictivo de riesgo vial en tiempo real, considerando restricciones de latencia, cobertura móvil, clima extremo e integración institucional.

**1. Objetivo de la guía**

Al finalizar la actividad, el estudiante será capaz de:

**Analizar un proceso organizacional, identificar sus problemas y oportunidades de mejora, y diseñar un proceso TO-BE donde la solución de software contribuya a generar valor para la organización.**

**Productos esperados**

* Identificación de actores y necesidades.
* Proceso actual **AS-IS**.
* Identificación de brechas.
* Proceso propuesto **TO-BE**.
* Identificación del aporte del software.
* Indicadores de valor.

**Regla:** primero se analiza y mejora el **proceso de la organización**; después se determina cómo el software lo soportará.

**3. Ejemplo aplicado: Seguridad Vial**

**3.1 Problema**

El proceso tradicional puede ser predominantemente reactivo:

Se produce una condición peligrosa → ocurre un incidente → se reporta → se atiende → se registra → posteriormente se analiza.

El proyecto busca cambiar hacia un enfoque preventivo mediante monitoreo y predicción del riesgo.

**3.2 Valor esperado**

| **Situación actual** | **Valor esperado** |
| --- | --- |
| Atención posterior al incidente | Prevención |
| Información histórica | Información en tiempo real |
| Reporte manual | Alertas oportunas |
| Decisiones reactivas | Decisiones preventivas |
| Información dispersa | Información integrada |

**12. Preguntas de análisis**

Al finalizar, el equipo debe responder brevemente:

1. **¿Qué problema del proceso organizacional se pretende resolver?**
2. **¿Qué actividad del AS-IS genera mayor pérdida de valor?**
3. **¿Qué cambia concretamente en el TO-BE?**
4. **¿Qué actividades serán automatizadas o mejoradas mediante software?**
5. **¿Cómo se demostrará que el nuevo proceso genera valor?**

**Criterio clave de evaluación**

El estudiante **no debe justificar el proceso diciendo solamente "se utilizará Scrum, DevOps o IA"**.

La argumentación correcta es:

**Problema organizacional → necesidad de cambio → proceso TO-BE → necesidad de software → resultado → valor → indicador.**

Este enfoque deja preparado el trabajo para el **Eje 2: Modelo de procesos de software**, donde, a partir del TO-BE obtenido, el estudiante podrá justificar por qué conviene utilizar **Agile, DevOps, MLOps, DataOps, Lean u otro modelo**, según las características particulares de su proyecto.
